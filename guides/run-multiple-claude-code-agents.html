Run multiple Claude Code agents at once on a Mac, without babysitting them

Parallel Claude Code sessions are easy to start and hard to keep moving. This guide covers every way to run them, from Anthropic's built-in agent view to plain worktrees and tmux, and how to always know which agent is waiting on you.

Last updated: October 19, 2026 · Cadence Labs

Short answer

Claude Code runs several sessions at once on its own. The quickest built-in way is agent view: run claude agents, type a task and press Enter, and each prompt becomes its own background session. The screen groups them into Needs input, Working, Ready for review and Completed. For sessions you drive yourself, start each with claude --worktree <name> so they edit separate copies of the repo.

Whatever you pick, set up a way to see which session is waiting. A parallel agent that sits on a permission prompt for twenty minutes is not running in parallel.

Seven ways to run Claude Code agents in parallel

  1. Separate terminals, one git worktree each. Full control, no setup beyond claude --worktree.
  2. tmux. The same, in named windows that keep running after you close the terminal.
  3. Agent view. Anthropic's dashboard for background sessions, opened with claude agents. Research preview.
  4. Subagents. Helpers inside one session that take a side task and report back.
  5. Agent teams. A lead session that splits work across teammates. Experimental and off by default.
  6. Projects. Parallel threads at claude.ai/code that run in the cloud. Public beta on Pro and Max.
  7. Cadence. A Mac app that puts every agent, Claude Code and other CLIs, on one toolbar and in one Inbox.

Anthropic compares its options in Run agents in parallel. The table near the end of this guide sums them up.

Split the work first

Claude Code has no problem running several times on one Mac. The trouble starts when two sessions edit the same file, or when one session's half-finished change breaks the build another is testing.

Good parallel tasks are ones you could hand to two people without a meeting: a bug in the API and a layout fix in settings, tests for one module and a refactor of another. Tasks that need each other's output go one after the other.

A useful pattern is many readers and one writer. Agents that only investigate can run in any number, because their output never conflicts. Keep the agents that change code to a few, each on its own area. More on this in Scouts before editors.

1. Separate terminals, one worktree each

A git worktree is a second checkout of the same repository in another folder, on its own branch. Agents in different worktrees cannot overwrite each other's files. Claude Code makes one for you:

claude --worktree search          # in one terminal
claude --worktree settings-dark   # in another

Each lands in .claude/worktrees/<name>/ on a branch named worktree-<name>. When you exit, Claude Code asks whether to keep a worktree that has changes. Add .claude/worktrees/ to .gitignore, and list files like .env in a .worktreeinclude file to copy them into new worktrees (worktrees docs).

To place the folder yourself, use git directly:

git worktree add ../my-app-search -b search
cd ../my-app-search && claude
git worktree remove ../my-app-search   # when you're done

A new worktree has no node_modules, virtualenv or build output, so install dependencies in each. Two dev servers on port 3000 will collide, so give each agent its own port.

2. tmux

Tabs work for two or three agents. tmux gives you named windows in one session that keep running when you close the terminal:

tmux new -s agents -n search      # first window
tmux new-window -t agents -n settings
# Ctrl-b w lists windows, Ctrl-b d detaches
tmux attach -t agents             # come back later

Run claude in each window from its worktree. With set -g monitor-bell on in ~/.tmux.conf, tmux flags a window when its program rings the bell.

3. Agent view (claude agents)

Agent view is one screen for Claude Code sessions running in the background. It is a research preview, so the keys may change.

claude agents                                  # open the dashboard
claude agents --cwd ~/Developer/my-app         # only one project
claude --bg "investigate the flaky settings test"   # dispatch from the shell
  • Type a prompt at the bottom and press Enter. Each prompt starts its own session, which moves into a worktree of its own before it edits files.
  • Sessions are grouped as Pinned, Ready for review, Needs input, Working and Completed. Ctrl+S groups by folder instead.
  • Space peeks at a session's latest output, and you can reply from there. To answer a permission prompt, attach with →; a reply typed in the peek panel waits in the queue instead.
  • A separate supervisor runs the sessions, so they keep going after you close agent view or the shell. They stop if the Mac shuts down.

Agent view is the strongest built-in answer if all your agents are Claude Code and you are happy in a terminal. Interactive sessions in other terminals do not appear until you send them to the background with /bg.

4 and 5. Subagents and agent teams

Subagents run inside one session. Claude hands a side task to a helper with its own context, such as searching a codebase or reviewing a diff, and gets a summary back. Define reusable ones in .claude/agents/, and add isolation: worktree to a definition to give each run its own worktree. The /batch skill splits one large change across 5 to 30 such subagents.

Agent teams go further: one session is the lead, it spawns teammates as separate Claude Code sessions, and they share a task list and message each other. Teams are experimental and off by default. Turn them on in ~/.claude/settings.json:

{ "env": { "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1" } }

Then ask for a team in plain words. Teammate permission prompts come to the lead session, teams use significantly more tokens than one session, and Anthropic suggests starting with three to five teammates (agent teams docs).

6. Projects in the cloud

A project at claude.ai/code or in the Claude desktop app is one ongoing conversation in which Claude starts parallel threads and shows which ones need you. Threads run in the cloud, so they keep going with your Mac off, or on your computer through Remote Control when you ask for that. It is a public beta on Pro and Max.

Know which one is waiting

This is where most parallel setups break down. Claude Code stops when it wants permission to run a command, asks a question, has a plan to approve, or finishes. With four sessions, the one that needs you is usually the one you are not looking at. Your options:

  • Agent view's Needs input group, if your sessions run there.
  • Desktop notifications. Built in for Ghostty, Kitty and iTerm2; Apple Terminal needs the bell setting or a hook. The notifications guide has the setup.
  • Your phone, through Remote Control or a push hook. See Claude Code on iPhone.

Each of these tells you that something is waiting. You still switch to that session, read back to see what it asked, and answer there.

7. Cadence: every agent in one Inbox

Cadence is a free macOS app that starts and tracks your coding agents and collects what they need in one Inbox. It fits when your agents are not all in one place: Claude Code next to Codex or Gemini, sessions in different terminals, some on a server.

Start the agents

  1. Download Cadence and make sure the claude CLI is installed and signed in. Cadence uses that login; there is no separate API key.
  2. On the toolbar at the edge of your screen, open ⋯ → New agent… and pick Claude Code.
  3. Choose Terminal (Claude Code's own interface, in Terminal, iTerm or Ghostty) or Cadence chat (runs inside Cadence, with real Allow/Deny cards, cost and a worktree per agent).
  4. Enter the Folder and an optional First message, then click Start.

Or double-tap ⌥ and say what you want. Talk sends it to the agent already working in that area, or starts a new one in the right folder. The voice control guide covers it.

See who is waiting, and answer

The toolbar shows one dot per agent: blue working, amber needs you, green done. Each agent gets a short title such as "settings page dark mode". Amber agents land in the Inbox as cards: questions with numbered options, plans to approve, and Allow/Deny requests. Press 1 to 9 to answer, J and K to move between cards, and Esc within two seconds to take an answer back.

Agents you did not start in Cadence

  • Claude Code running in Terminal or iTerm shows on the toolbar after a thin divider. Click a dot to jump to that tab.
  • Turn on Settings → Agents → Your own terminals and claude, codex or pi typed in any terminal runs through Cadence, so you can answer it from the Inbox, by voice or from your phone.
  • Since 0.5.7, agents on a Linux server show up too, labeled with the server's name. See Run Claude Code on a remote server.

When there are too many

Sets put a group of terminal agents away: their windows close, the agents keep running, and their questions still reach the Inbox. Say "is anything stuck?" and the Director answers across all of them. Away from the desk, the toolbar's ⋯ menu keeps the Mac awake until your agents finish, and the iPhone app, in a private TestFlight beta, takes the Inbox with you.

Common questions

How many Claude Code sessions can I run at once?

Claude Code does not stop you from starting more sessions. The practical limits are your plan's usage limits, which every session draws on, your machine's memory when each agent runs builds and tests, and how many results you can review. Most people find a handful of writing agents plus a few read-only ones is the useful range.

What is the difference between subagents and agent teams?

Subagents work inside one session: Claude hands them a side task and they report a summary back. Agent teams are separate Claude Code sessions run by a lead, with a shared task list and direct messages between teammates. Teams are experimental, off by default, and use significantly more tokens.

Do parallel Claude Code sessions share context?

No. Each session has its own conversation. They do read the same project files, including CLAUDE.md, so instructions you put there apply to all of them. Claude Code's cross-session messaging can pass findings between sessions when you ask it to.

Can two agents work in the same folder?

They can, but they may overwrite each other's edits or break each other's builds. Start each one with claude --worktree and a name, or make a git worktree yourself. Sessions you dispatch from agent view move into a worktree of their own before they edit, and Cadence chat agents get one automatically.

Can I run the agents on a server instead of my Mac?

Yes. Install Claude Code on a Linux server, run the sessions inside tmux or herdr, and connect from your Mac over SSH. Cadence 0.5.7 can show a server's agents on your toolbar and in your Inbox next to the local ones. The server guide walks through it.
