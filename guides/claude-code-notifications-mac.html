Claude Code notifications on Mac when it needs input, and when it's done

Claude Code pauses whenever it needs a permission, an answer or a plan approval, and when it finishes. Here is how to find out on a Mac without watching the terminal, and which setup works in which terminal.

Last updated: October 19, 2026 · Cadence Labs

Short answer

In Ghostty, Kitty and iTerm2, Claude Code already posts a macOS notification when it finishes or stops for a permission prompt while you are away from the window. In Apple Terminal and most other terminals it does not. There, add "preferredNotifChannel": "terminal_bell" to ~/.claude/settings.json to ring the bell, or add a Notification hook and a Stop hook that run osascript to post a real notification in any terminal. Both setups are below.

With several agents, a notification only says that one is waiting. Cadence shows every agent's state on a toolbar and lets you answer from one Inbox.

When Claude Code waits for you

Claude Code stops and waits in four situations:

  • A permission request. It wants to run a shell command, edit a file or use a tool your settings do not allow yet.
  • A question. It asks you to pick between options before it goes on.
  • A plan. In plan mode it waits for you to approve the plan or keep planning.
  • Done. It finished the turn and is waiting for your next message.

In each case nothing happens until you answer. A long task that stopped on a permission prompt two minutes in is the most common way to lose an afternoon.

A Notification hook works in every terminal, because the hook posts the notification itself. Anthropic covers the built-in behavior in Configure your terminal.

Option 1: built-in notifications and the bell

Claude Code fires its notification when it finishes a task or pauses for a permission prompt and you appear to be away from the terminal. In Ghostty, Kitty and iTerm2 that becomes a macOS banner with no setup. The notification also travels back over SSH, so a session on a server can alert you on your Mac. Ghostty and Kitty forward it as is. In iTerm2, if banners do not appear, and for sessions over SSH, open Settings → Profiles → Terminal, check Notification Center Alerts, click Filter Alerts and enable Send escape sequence-generated alerts.

Everywhere else, tell Claude Code to ring the terminal bell instead:

{
  "preferredNotifChannel": "terminal_bell"
}

Add that to ~/.claude/settings.json. What the bell does is up to the terminal. In Apple Terminal, check Settings → Profiles → Advanced: if you accepted Claude Code's first-run terminal setup, it turned Audible bell off there, so turn it back on, or use the visual bell and Dock options in the same section. In tmux, set -g monitor-bell on marks the window that rang.

The bell needs no scripts, but it is easy to miss and does not say which project it came from.

Option 2: hooks and macOS notifications

Hooks are shell commands Claude Code runs at fixed points. They run alongside the built-in notification and work in any terminal, including Apple Terminal. Two of them cover what you want:

  • Notification runs when Claude Code needs permission to use a tool, or when your input has been idle for a while.
  • Stop runs when Claude Code finishes responding.

Step 1: write a small script

Save this as ~/.claude/hooks/notify.sh. It reads the event Claude Code sends on standard input, takes the message and the project folder, and posts a notification. It uses jq (brew install jq).

#!/bin/sh
input=$(cat)
msg=$(printf '%s' "$input" | jq -r '.message // "Finished"')
dir=$(printf '%s' "$input" | jq -r '.cwd // empty' | xargs basename)
osascript -e 'on run argv' \
  -e 'display notification (item 1 of argv) with title (item 2 of argv) sound name "Glass"' \
  -e 'end run' "$msg" "Claude Code: $dir"

Make it executable with chmod +x ~/.claude/hooks/notify.sh. Passing the text as arguments, instead of pasting it into the AppleScript, keeps quotes in Claude's message from breaking the command.

Step 2: register the hooks

Add this to ~/.claude/settings.json (merge it with anything already there):

{
  "hooks": {
    "Notification": [
      { "matcher": "", "hooks": [ { "type": "command", "command": "~/.claude/hooks/notify.sh" } ] }
    ],
    "Stop": [
      { "matcher": "", "hooks": [ { "type": "command", "command": "~/.claude/hooks/notify.sh" } ] }
    ]
  }
}

To be told only about permission requests, set the Notification matcher to "permission_prompt" and drop the Stop entry.

Step 3: test it

Start a new Claude Code session, since sessions load hooks when they start. Run /hooks to check that both are listed, then ask for something that needs a permission. If no banner appears, open System Settings → Notifications: notifications from osascript are listed under Script Editor, and a Focus mode can hide them.

Where notifications fall short

Notifications are a real improvement for one or two sessions. With more, a few gaps show up:

  • A banner says something is waiting, but you still find the right tab and scroll back to see the question.
  • Banners pile up in Notification Center with no sense of which ones you already handled.
  • Nothing shows the overall state: which agents are working, which are done, which are stuck. Claude Code's agent view does this for background sessions; the multiple agents guide covers it.

Option 3: notifications on your phone

If you leave the desk, a Mac banner does not help. With Anthropic's Remote Control and the Claude app, run /config and turn on Push when actions required to get a push for permission prompts and questions, which you can then answer from the phone. On any plan, the same hook events can send a push through ntfy or Pushover. Claude Code on iPhone has both setups.

Option 4: Cadence's toolbar and Inbox

Cadence is a free macOS app that watches your coding agents and collects what they need from you.

Set it up

  1. Download Cadence. Agent features use your existing claude login.
  2. Start Claude Code from ⋯ → New agent… on the toolbar, or double-tap ⌥ and ask for the work with Talk.

For Claude Code agents it starts in a terminal, Cadence adds its own hook through Claude Code's --settings flag, so your ~/.claude/settings.json stays as it is. The hook records Claude's exact question or permission request, so the Inbox shows the full text instead of what fit on screen.

Claude Code you started yourself in Terminal or iTerm shows up too, after a thin divider on the toolbar. Click its dot to jump to that tab; its Inbox card offers Answer in Terminal. Turn on Settings → Agents → Your own terminals and claude typed in any terminal runs through Cadence, so you can answer it right in the Inbox.

See state at a glance

The toolbar on the edge of your screen has one dot per agent: blue working, amber needs you, green done. The Inbox button shows how many agents are waiting. When nothing needs you, the toolbar folds into a small notch that shows only the dots, and it opens again when something lands in the Inbox.

Answer without switching windows

The Inbox lists every waiting card: questions with numbered options, plans with Approve the plan or Keep planning, and permission requests with Allow or Deny. Press 1 to 9 to answer, Space to type, or V to speak. A typed "no, use yarn instead" on a permission card denies it and passes your reason to the agent. Finished work arrives as a card with a short recap.

Sound and banners

In Settings → Agents, Text-to-speech reads agent completions and approval requests aloud (voice and rate are adjustable), and Notifications turns macOS notifications for agent events on or off.

Common questions

Does Claude Code send notifications in Apple Terminal?

Not desktop notifications. Claude Code sends those only in Ghostty, Kitty and iTerm2. In Apple Terminal, set preferredNotifChannel to terminal_bell in ~/.claude/settings.json and make sure the bell is on in Terminal's profile, or add a Notification hook that runs osascript.

Why does my Claude Code hook not show a notification?

Check three things: the script is executable, you started a new session after editing settings, and macOS allows notifications from Script Editor, which is where osascript notifications come from. Focus modes can also hide them.

Can Claude Code notify me when it is done?

Yes. The built-in notification fires when Claude finishes or pauses for a permission prompt while you appear to be away from the terminal. For a notification after every response, add a Stop hook pointing at the same script as the Notification hook.

Can I get Claude Code notifications on my phone?

Yes. With Remote Control and the Claude app, turn on Push when actions required in /config. On any plan, a Notification hook can send a push through ntfy or Pushover.

Does Cadence change my Claude Code settings?

No. Cadence passes its hook to the Claude Code sessions it starts with the --settings flag. Your own ~/.claude/settings.json and its hooks keep working. The optional Your own terminals switch adds one line to ~/.zshrc, and you can turn it off any time.
