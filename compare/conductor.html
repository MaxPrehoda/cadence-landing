Cadence vs Conductor an inbox or a workspace manager

Conductor and Cadence both help you run several coding agents on a Mac, but they start from different places. Conductor manages where each agent works. Cadence manages what each agent needs from you.

Updated October 19, 2026 · Cadence Labs

Short answer

Conductor and Cadence solve different problems. Conductor is a workspace manager: every task gets its own git worktree and branch, an agent (Claude Code, Codex, Cursor or OpenCode) works in it, and you review the diff, open a pull request and merge from the same app. Cadence does not create workspaces. It sits over the agents you already run in terminals, shows which one needs you, and lets you answer all of them from one Inbox, by keyboard, voice or phone.

Pick Conductor if your bottleneck is keeping parallel changes apart and reviewing them. Pick Cadence if it is noticing which agent is waiting and answering it quickly. Both have a free tier that uses your own agent subscriptions.

What Conductor does well

Conductor, from Melty Labs, is built around one idea: every task is a workspace. When you create one, Conductor makes a git worktree on a new branch, so agents working on different tasks never touch each other's files. You chat with the agent in that workspace, review its diff, open a pull request and merge, all in one window. When you are done, you archive the workspace.

It bundles Claude Code, Codex and OpenCode and runs Cursor through Cursor Agent, using your own logins or API keys. Pro adds cloud workspaces that keep running after you close the app, an iPhone app for them, and multiplayer for up to five Pro users.

If you want a guided flow from "new task" to "merged PR", with isolation you never have to think about, Conductor is a strong choice, and Cadence does not try to replace it.

What Cadence does differently

Cadence leaves your workflow where it is. You keep running agents in terminals, in folders and branches you pick, and Cadence watches all of them:

  • A toolbar over every app. One dot per agent on the edge of your screen: blue working, amber needs you, green done. You see a waiting agent without opening a window.
  • One Inbox across agents and CLIs. Questions, plan approvals and Allow/Deny requests from Claude Code, Codex and the rest arrive as cards with numbered options. Press 1 to 9, and Esc within two seconds to take it back.
  • Voice. Double-tap ⌥ and say "tell the billing agent to add retries"; Talk finds the agent already on that work or starts one in the right folder. Hold ⌥ to dictate into any app. Speech is transcribed on your Mac.
  • The Director. A Claude session that sees every agent and answers "what is left before I can ship?"
  • More CLIs. Through herdr, Cadence also covers Pi, Omp, Amp, Grok, Copilot, Gemini and Aider, and since 0.5.7 agents on your Linux servers.
  • Free, no account. No GitHub sign-in, no Cadence account, no paid tier.

What it does not do: give every agent a worktree automatically (only Claude Code in Cadence chat mode gets one), open pull requests, or run agents in the cloud.

Which one to pick

Conductor is the better pick if

  • you want each task isolated in its own worktree and branch without setting it up yourself, for every agent;
  • you review and merge agent work as pull requests and want that in the same app;
  • you want agents in the cloud that keep going after you close the app, or a shared workspace for a team;
  • you use an Intel Mac.

Cadence is the better pick if

  • you already run agents in terminals and want to keep doing that;
  • you run many agents and the cost is the minutes each one sits waiting before you notice;
  • you want to answer by voice, or from your iPhone, without opening each agent;
  • you mix several CLIs, or run agents on your own Linux servers;
  • you do not want to sign in to anything.

Using both

They can share a Mac. One way to divide the work: Conductor for feature work that should end as a reviewed pull request, and terminals with Cadence for quick fixes, investigations and agents on other CLIs. Neither app needs the other, and both use your own agent subscriptions.

Common questions

Is Cadence a Conductor alternative?

For some people. If you want worktree workspaces with built-in review and merge, Conductor is the better fit. If you want to keep your agents in terminals and answer all of them from one Inbox, Cadence fits better, and it is free with no account.

Does Conductor work with Codex and Cursor?

Yes. Conductor runs Claude Code, Codex, OpenCode and Cursor. Other CLIs, such as Amp, Pi, Copilot and Gemini, run in its experimental terminal mode.

Does Cadence create git worktrees like Conductor?

Only for Claude Code in Cadence chat mode, where each agent gets a branch named cadence/<name>-<id> in ~/.cadence/worktrees/. For terminal agents, create a worktree yourself and choose it as the agent's folder.

Is Conductor free?

Conductor's Free plan runs parallel agents in local workspaces with your own subscriptions and keys. Cloud workspaces, the mobile app and collaboration are part of Pro at $50 a month; Teams is $60 per user a month.

Try Cadence
